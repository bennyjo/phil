## Real finding this cycle: position-monitoring price-direction misread

`strategy/schedule.json`'s 12:55Z note read the Tokyo position as
"essentially confirmed won (ask now 0.001 vs 0.089 entry, no bid)" — this
was backwards. The position holds the **No** token. `quote.py` reports
the book for the exact token_id held, so a No-token ask collapsing from
0.089 toward 0.001 means the market was pricing No as near-certain to
**lose** (Yes near-certain), not win. The position did in fact lose. The
monitoring note called a large adverse move (−0.088, effectively total)
a favorable one by eyeballing "the number is small" instead of comparing
direction against entry and the side held.

This is the exact failure the "adverse move ≥0.10 from entry must be
called out explicitly" rule (playbook §Open-position monitoring) exists
to catch, but the rule doesn't state which direction is adverse for a
short/No-side hold, and the misreading cycle didn't do the entry-vs-mid
subtraction explicitly enough to catch its own sign error. Fixing this in
the playbook now — see diff below — since a future position (any No-side
hold, or a Yes-side hold that collapses toward 0 the same way) will hit
the identical trap otherwise.

## Playbook edit

Added an explicit sign-check line to §Open-position monitoring: state the
adverse/favorable move as `(live_mark_for_held_side - entry)`, signed, not
just "the ask moved" — a token price near 0 is adverse for a position
holding that exact token, not favorable, regardless of how small the
absolute number looks.
